1 The Concept

DAX.OSI is a desktop application that simulates an entire operating system inside a single window — complete with a boot screen, login, desktop, and bundled apps.

DOSI.CORE is the engine that powers it: window management, system settings, theming, animations, a UI control library, and a project/designer system for building new DOSI apps.

Mental model: DAX.OSI is the shell you see and click. DOSI.CORE is the library it (and your future apps) depend on.

2 Run It

From the repository root, build and launch the shell:

git clone https://github.com/Kruox/DAX.OSI-Master.git
cd DAX.OSI-Master
dotnet build
dotnet run --project DAX.OSI

On first launch a SystemSettings.json file is created next to the executable. You can edit it to change the default accent or fullscreen behavior.

3 The Boot Flow

What happens when you press play:

Program.MainApp startup
App.InitializeTheme + SystemCore
BootScreenSplash + animation
LoginScreenUserManager
DesktopScreenWindowManager

ScreenManager swaps between these full-screen surfaces, while WindowManager takes over once the desktop appears, hosting every opened app as a draggable, snappable DOSIWindow.

4 Using DOSI.CORE

Most system features go through a small set of static entry points:

// Boot the engine + load SystemSettings.json
SystemCore.Initialize();

// Apply the saved accent to all DOSI controls
AccentManager.Instance.InitializeFromSettings();

// Show a window on the desktop
WindowManager.Instance.Open(new MyAppWindow());

// Push a toast notification
DOSIPopNotification.Show("Welcome", "DAX.OSI is ready.");

// Cleanly shut the system down
SystemShutdown.Begin();

The DOSI.CORE.UIComponents namespace provides the styled controls: DOSIWindow, DOSIButton, DOSITextBox, DOSIDialog, DOSICodeEditor, and more — all themed by the active AccentManager.

5 Your First DOSI App

A DOSI app is, at its simplest, a class that derives from DOSIWindow and is launched through WindowManager:

using DOSI.CORE.UIComponents;
using DOSI.CORE.UIComponents.WindowManagement;

public class HelloApp : DOSIWindow
{
    public HelloApp()
    {
        Title  = "Hello, DOSI!";
        Width  = 480;
        Height = 280;

        var button = new DOSIButton { Content = "Click me" };
        button.Click += (_, _) =>
            DOSIPopNotification.Show("Hi", "You clicked the button!");

        Content = button;
    }
}

// Launch it from anywhere in the shell:
WindowManager.Instance.Open(new HelloApp());
Tip: For richer apps, explore DOSI.CORE.ProjectSystem and DOSI.CORE.Designer — they let you author DOSIProject packages with a visual form designer and compile them into apps that register with DOSIPublishedAppRegistry.

6 Inside DOSIIDE

From the desktop, launch the Code app — that's DOSIIDE, your in-OS development environment. It's sandboxed to your user folder and gives you a Visual-Studio-style layout:

ToolbarNew · Build · Run · Publish
Solution Exploreryour home folder
Tabs + Editorcode or designer
Output Panebuild log + run preview

Behind the scenes the IDE uses Roslyn to compile your project in-memory, then reflectively invokes its entry point. Anything written to Console.Out is captured into the Output pane, and any returned Control is hosted in a live DOSIWindow on the desktop.

7 Creating a Real Project

Press the New Project button. DOSIIDE scaffolds a folder under ~/Projects/<name>/ with a .dosiproj manifest:

{
  "Name":        "MyCoolApp",
  "Kind":        "DOSIControl",
  "EntryType":   "Program",
  "EntryMethod": "Run",
  "FormatVersion": 1
}

The convention is simple: write a static Run() method that returns either void (script-like) or an Avalonia Control (UI app):

using Avalonia.Controls;
using DOSI.CORE.UIComponents;

public static class Program
{
    public static Control Run()
    {
        var stack = new StackPanel { Spacing = 8, Margin = new(16) };
        stack.Children.Add(new DOSILabel  { Text = "Hello from a DOSI app!" });
        stack.Children.Add(new DOSIButton { Content = "OK" });
        return stack;
    }
}
Even shorter: DOSIIDE allows top-level statements. A file containing just var btn = new DOSIButton { Content = "Hi" }; return btn; compiles too — the compiler auto-wraps it.

8 Going Multi-File

Add as many .cs files as you need. Every source under the project folder (excluding bin/ and obj/) is compiled together as one assembly. A typical layout:

MyCoolApp/
├── MyCoolApp.dosiproj
├── Program.cs            ← entry point with static Run()
├── Models/
│   └── TodoItem.cs
├── Views/
│   └── TodoView.cs       ← your own DOSIWindow subclass
└── MainForm.dosiform     ← visual designer file (optional)
// Views/TodoView.cs
using DOSI.CORE.UIComponents;
using DOSI.CORE.UIComponents.WindowManagement;

public class TodoView : DOSIWindow
{
    public TodoView()
    {
        Title = "Todo";
        WindowWidth  = 420;
        WindowHeight = 320;
        Content = new DOSILabel { Text = "My todos go here" };
    }
}

// Program.cs
public static class Program
{
    public static void Run() => WindowManager.Instance.Open(new TodoView());
}

9 Using the Visual Designer

Right-click in the Solution Explorer and add a .dosiform file. DOSIIDE will open it in DOSIDesigner instead of the code editor:

  • Toolbox — drag any DOSI control onto the canvas
  • Selection — click to select, arrow keys to nudge, corner handles to resize
  • Snap-to-grid — 8 px grid with overlay
  • Property grid — live edit Name, Text, Width, Dock, etc.

The form is persisted as JSON. At runtime, DOSIFormLoader turns it back into a real DOSIWindow — so even a project with no .cs files can still Run.

// Snippet from a .dosiform document
{
  "Title": "Login",
  "Width": 400, "Height": 240,
  "Controls": [
    { "Type": "DOSILabel",  "Name": "label1",  "X": 20, "Y": 20, "Properties": { "Text": "Username" } },
    { "Type": "DOSITextBox","Name": "userBox", "X": 100,"Y": 20, "Width": 260 },
    { "Type": "DOSIButton", "Name": "okBtn",   "X": 280,"Y": 180,"Properties": { "Content": "Sign In" } }
  ]
}

10 Event Handlers & Docking

Each designed control has a Handlers dictionary mapping event name → C# body. DOSIIDE compiles them into one synthetic class and binds each method to the live instance — no boilerplate required.

// In the designer, set okBtn.Click handler body to:
if (string.IsNullOrWhiteSpace(userBox.Text))
    DOSIPopNotification.Show("Oops", "Username is required.");
else
    DOSIPopNotification.Show("Welcome", "Hi, " + userBox.Text + "!");

Form-level events (Load, Closing) are stored under the synthetic control name Form and wired to the host window.

Make your forms responsive with the Dock property:

Noneabsolute X/Y
Topfull-width header
Leftsidebar
Fillmain content
Bottomstatus strip

11 Advanced Patterns

You have the full DOSI.CORE surface available. A few ideas to push further:

// Persist your own settings alongside SystemSettings.json
var path = System.IO.Path.Combine(
    System.AppContext.BaseDirectory, "MyApp.settings.json");
System.IO.File.WriteAllText(path,
    System.Text.Json.JsonSerializer.Serialize(new { Theme = "Dark" }));

// React to accent changes globally
AccentManager.Instance.AccentChanged += (_, _) =>
    DOSIPopNotification.Show("Theme", "Accent updated!");

// Spawn a modal dialog
var dlg = new DOSIDialog("Confirm", "Delete this item?");
dlg.AddButton("Yes", () => { /* delete */ });
dlg.AddButton("No",  () => { });
WindowManager.Instance.Open(dlg);

// Animate a control
Tween.Animate(myControl, OpacityProperty, from: 0, to: 1,
              duration: 250, easing: Easings.EaseOutCubic);
Pro tip: Open the existing default apps in DAX.OSI/DefaultApplications/ as living examples — DOSIFileExplorer, DOSITerminal, and the IDE itself all use the exact same APIs you do.

12 Publishing Your App

When your project builds and runs cleanly, hit the Publish (↑) button. DOSIIDE registers it with DOSIPublishedAppRegistry:

// Conceptually equivalent to what Publish does:
DOSIPublishedAppRegistry.Register(myProject);

// After publishing, any code in the OS can launch it:
var window = DOSIPublishedAppRegistry.Launch("MyCoolApp");
WindowManager.Instance.Open(window);

Your app now appears on the desktop alongside built-ins like Terminal and File Explorer — a real, first-class DOSI citizen.
